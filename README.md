# AutoQV

VRChat の QvPen などのペンワールドギミックでの筆記を自動化する、Windows 向けの CLI ツールです。

文字のストロークデータを元に、相対マウス移動で視点を動かしてクロスヘアを文字の軌跡通りになぞらせ、マウスボタンの押下/解放でペンの上げ下げを制御して書きます。

> **開発中です。** `write`(実際にマウスを動かして書く)と `preview`(入力を送らずに経路を確認する)が使えます。英数字・記号・ひらがな・カタカナ・漢字のストロークデータは、必要になったときに自動で取得します。

## 動作環境

- Windows 10 / 11
- VRChat(QvPen などのペンが使えるワールド)

## 使い方(exe から実行)

`autoqv.exe` をコマンドプロンプトまたは PowerShell から実行します。exe の場所で次のように入力してください。

```powershell
.\autoqv.exe --help
.\autoqv.exe write --help
.\autoqv.exe preview --help
.\autoqv.exe check --help
```

### `write`: 書く

```powershell
.\autoqv.exe write "HELLO"
.\autoqv.exe write --file message.txt
```

1. コマンドを実行すると(初回はストロークデータを取得してから)、配置結果のサマリーを表示して待機状態になります。この間、マウスやキーボードの入力は一切送りません
2. VRChat のウィンドウに切り替え、ペンを持って書きたい位置にクロスヘアを合わせます(書き始めの位置が文字の左上になります)
3. **`Alt+P`** で書き始めます
4. **`Alt+C`** で中断できます(待機中に押すと何も書かずに終了します)。Ctrl+C でも中断できます

中断・終了時は、押していたマウスボタンを必ず離します。ホットキーはウィンドウのフォーカスに関係なく動作します。

テキストは `<TEXT>` 引数か `--file <PATH>`(UTF-8)のどちらか一方で指定します。`--dry-run` を付けると入力を送らず、サマリーだけ表示して終了します。

`write` では、`preview` のオプションに加えて次のオプションを使えます。

| オプション | 内容 | 既定値 |
| ---------- | ---- | ------ |
| `--button <BUTTON>` | ペンを下ろすために押すマウスボタン(`left` / `right` / `middle`) | left |
| `--start-hotkey <KEY>` | 書き始めるホットキー | `Alt+P` |
| `--abort-hotkey <KEY>` | 中断するホットキー | `Alt+C` |
| `--dry-run` | 入力を送らず、サマリーだけ表示して終了します | なし |

ホットキーは `Alt+P` や `Ctrl+Shift+F8` のように指定します。修飾キーは `Ctrl` / `Alt` / `Shift` / `Win`、キーは英字・数字・`F1`〜`F24`・`Esc`・`Space`・`Enter`・`Tab` です。英字・数字・`Space`・`Enter`・`Tab` は修飾キーが必須です。開始と中断には別のキーを指定してください。

#### 未収録文字のログ

ストロークデータに無い文字はスキップし、画面に表示するとともに、ログファイルに追記します(`--dry-run` でも記録します)。ログは 1 行 1 件の JSON です。

```json
{"timestamp":"2026-10-22T00:00:00Z","char":"ん","codepoint":"U+3093","line":1,"column":2}
```

既定の保存先は `%APPDATA%\Harukoto Project\AutoQV\autoqv-missing-glyphs.log` です。

### `preview`: 経路の確認

指定したテキストを書いた場合の経路を計算し、サマリーだけを表示します。マウスやキーボードの入力は送りません。

```powershell
.\autoqv.exe preview "Hello"
```

表示される内容:

- 配置した文字数、ストローク数、全体の大きさ(em)
- ペンダウン回数、移動回数、描画距離・ペンアップ移動距離(マウスカウント)
- 推定所要時間
- ストロークデータに無かった文字(行・列つき。最大 20 件)

#### オプション

| オプション | 内容 | 既定値 |
| ---------- | ---- | ------ |
| `--config <PATH>` | 設定ファイル(後述) | 実行ファイルと同じ場所の `autoqv.toml`(あれば) |
| `--glyph-file <PATH>` | ストロークデータの JSON ファイル。自動取得したデータに重ねて使います。複数指定でき、後のものが優先されます | なし |
| `--offline` | ストロークデータをダウンロードせず、キャッシュと `--glyph-file` だけを使います | 無効 |
| `--size <N>` | 文字の大きさ(フォントサイズ)の倍率。縦横とも拡大・縮小します | 1.0 |
| `--width-scale <N>` | 文字の横幅の倍率(`--size` に対する相対値)。`0.6` なら横幅が 6 割になります(平体)。文字の送り幅も同じ割合で変わり、縦の大きさと字間は変わりません | 1.0 |
| `--char-spacing <N>` | 字間(文字サイズに対する比)。負の値で詰められます(最小 -1.0)。ひらがな・カタカナ・漢字は送り幅が 1em の枠いっぱいなので、字間 0 でも枠が接するだけで広く見えます。`-0.1` 前後で試してください | 0.15 |
| `--line-spacing <N>` | 行間(文字サイズに対する比) | 0.4 |
| `--line-width-em <EM>` | 1 行の最大幅(em)。超えると折り返します | 20.0 |
| `--no-kinsoku` | 行頭禁則処理(句読点・閉じ括弧を行頭に置かない)を無効にします | 有効 |
| `--counts-per-em <N>` | 1 em あたりのマウスカウント数(縦横共通) | 400 |
| `--counts-per-em-x <N>` / `--counts-per-em-y <N>` | 軸ごとのカウント数(`--counts-per-em` より優先) | 400 |
| `--step-delay-ms <MS>` | マウス移動 1 ステップごとの待機時間 | 4 |
| `--max-counts-per-step <N>` | 描画中の 1 ステップあたりの最大カウント数 | 4 |
| `--move-speed-multiplier <N>` | ペンを上げて移動するときのステップ量の倍率 | 3.0 |
| `--min-pen-down-interval-ms <MS>` | ペンダウン(ボタン押下)から次のペンダウンまでの最短間隔。`0` で無効 | 230 |
| `--pen-down-settle-ms <MS>` | 視点の移動が終わってから、ペンダウン(ボタン押下)するまでの待機時間。`0` で無効 | 30 |
| `--pen-down-delay-ms <MS>` | ペンダウン(ボタン押下)の直後、描画の移動を始めるまでの待機時間。`0` で無効 | 30 |
| `--pen-up-delay-ms <MS>` | ペンアップ(ボタン解放)の直後、次の移動を始めるまでの待機時間。`0` で無効 | 30 |

数値は、サイズ・感度・速度・待機時間が正の値、行間・ペンダウン間隔が 0 以上の値、字間が -1.0 以上の値のみ指定できます。字間を負にしても、次の文字の位置が前の文字より左に戻ることはありません。

#### ペンダウン間隔と消しゴムモード

QvPen は、短い間隔(0.2 秒未満)で近い位置を続けて押すとダブルクリックとみなし、ペンと消しゴムを切り替えます。`口` や `日` のように前のストロークの近くから次のストロークを書き始める文字で誤って消しゴムに切り替わらないよう、AutoQV は直前のペンダウンから `--min-pen-down-interval-ms` 経過するまで次のペンダウンを待ちます(位置にかかわらず常に待ちます)。既定値 230 ms は QvPen の判定時間に余裕を加えた値です。ペンの種類やワールドの設定が異なる場合は調整してください。

#### ペンの押下・解放後の待機

VRChat はボタンの押下・解放を 1〜数フレーム遅れて処理します。待ち時間が無いと、ボタンを離した直後の移動が「まだ書いている」状態で行われ、文字と文字の間(や画と画の間)に線が引かれたり、書き始めの位置がずれたりします。AutoQV はボタンを離した後に `--pen-up-delay-ms`、押した後に `--pen-down-delay-ms` だけ待ってから次の移動を送ります。また、視点の移動が反映される前にボタンを押さないよう、押す直前に `--pen-down-settle-ms` だけ待ちます。線がつながる場合は `--pen-up-delay-ms` を、書き始めが欠ける・ずれる場合は `--pen-down-delay-ms` と `--pen-down-settle-ms` を増やしてください。推定所要時間にも反映されます。

### `check`: 未収録文字の確認

テキスト中の、ストロークデータに無い文字を一覧表示します。経路の計算や入力の送信は行いません。

```powershell
.\autoqv.exe check "A🙂🙂"
.\autoqv.exe check --file message.txt
```

```
Characters checked : 3
With stroke data   : 1
Missing glyphs     : 2 (1 unique)
  '🙂' (U+1F642) x2
```

- 未収録の文字は重複をまとめ、初めて現れた順に「文字・コードポイント・出現回数」で表示します
- 未収録の文字があっても終了コードは 0 です。未収録文字のログファイルには記録しません
- テキストは `<TEXT>` 引数か `--file <PATH>`(UTF-8)のどちらか一方で指定します
- `--glyph-file` と `--offline` を使えます(意味は `preview` と同じ)。ストロークデータが必要なため、`write` / `preview` と同様に不足分は自動取得します

### 設定ファイル(`autoqv.toml`)

感度・速度・レイアウトなどを TOML ファイルに保存できます。`autoqv.exe` と同じ場所に `autoqv.toml` を置くと自動で読み込まれます。別の場所のファイルは `--config <PATH>` で指定します(指定したファイルが無い場合はエラーになります)。

すべての項目は省略できます。省略した項目は既定値になります。優先順位は「コマンドラインオプション > 設定ファイル > 既定値」です。

```toml
[sensitivity]
counts_per_em_x = 400.0
counts_per_em_y = 400.0

[pen]
button = "left"
step_delay_ms = 4
max_counts_per_step = 4
move_speed_multiplier = 3.0
min_pen_down_interval_ms = 230
pen_down_settle_ms = 30
pen_down_delay_ms = 30
pen_up_delay_ms = 30

[layout]
size = 1.0
width_scale = 1.0
char_spacing = 0.15
line_spacing = 0.4
line_width_em = 20.0
kinsoku = true

[log]
missing_glyph_log = "autoqv-missing-glyphs.log"

[safety]
start_hotkey = "Alt+P"
abort_hotkey = "Alt+C"
```

- 知らないキーやセクション名はエラーになります(タイプミスで設定が無視されないようにするためです)
- `missing_glyph_log` の相対パスは `%APPDATA%\Harukoto Project\AutoQV` が基準です。絶対パスも指定できます

#### 感度の調整

`counts_per_em_x` / `counts_per_em_y` は、文字の 1 em(文字の高さ・幅の基準)を書くのに送るマウスカウント数です。VRChat のマウス感度や視点の距離によって適切な値が変わるため、短い文字で試しながら調整してください。縦横で比率が合わない場合は、軸ごとに別の値を設定します。

### ストロークデータの自動取得

`write` と `preview` は起動時にストロークデータが揃っているかを確認し、足りないときだけダウンロードします。

- 英数字・記号(Hershey Roman Simplex)とひらがな・カタカナ(KanjiVG)は、初回に 1 回だけまとめて取得します。ひらがな・カタカナは約 180 文字ぶんで、数十秒かかることがあります
- 漢字(KanjiVG)は、書く文章に含まれていて、まだ取得していない文字だけをその都度取得します。一度取得した漢字は次回以降は取得しません
- KanjiVG に無い漢字(一部の異体字など)は未収録の文字として扱われ、次回以降も取得を試みません
- 取得したデータは `%APPDATA%\Harukoto Project\AutoQV` にキャッシュされます。2 回目以降はネットワークに接続せずに動作します
- 取得元は特定のコミットに固定されており、ダウンロードしたファイルはチェックサムで検証します
- 英数字・記号・ひらがな・カタカナの取得に失敗した場合はエラーで終了します。ネットワークを確認するか、`--glyph-file` でデータを指定してください。取得済みの分は保存されるので、再実行すると続きから取得します
- 漢字の取得に失敗した場合は警告を表示し、その漢字を未収録として扱って続行します
- `--offline` を付けると、ダウンロードを一切行いません。キャッシュが無い場合は、`--glyph-file` で指定したデータだけを使います

### ストロークデータを自分で用意する(`--glyph-file`)

次の形式の JSON ファイルを `--glyph-file` で指定すると、自動取得したデータに重ねて使えます(同じ文字があればこちらが優先されます)。自動取得に含まれない文字(全角記号など)を書きたいときや、オフラインで使うときに利用します。

```json
{
  "version": 1,
  "glyphs": {
    "I": {
      "advance": 0.5,
      "strokes": [[[0.25, 0.1], [0.25, 0.9]]]
    },
    "L": {
      "advance": 0.6,
      "strokes": [[[0.2, 0.1], [0.2, 0.9], [0.5, 0.9]]]
    }
  }
}
```

- 座標は 0.0〜1.0 の正方形(原点は左上、y は下向き)で表します
- `strokes` は「ストロークの配列 → 点の配列 → `[x, y]`」です
- `advance` は次の文字までの送り幅で、0 より大きい値にします
- キーは 1 文字だけにします

## 注意

- VRChat が管理者権限で動作している場合は、AutoQV も管理者権限で起動する必要があります(通常権限の入力は無視されます)
- 書き始めの位置は、待機中に合わせたクロスヘアの位置です。書き始める前に、ペンの位置と書き込める範囲を確認してください
- 書いている間は、マウスを動かしたりウィンドウを切り替えたりしないでください。位置がずれたり、別のウィンドウに入力が送られたりします
- コンソールウィンドウを閉じて終了すると、ボタンが押されたままになる場合があります。終了は `Alt+C` か Ctrl+C を使ってください
- 使用するワールドや VRChat の利用規約・ルールに従ってください

## 開発者向け

### 前提

- Rust(edition 2024 に対応した安定版)
- Windows(`SendInput` と `RegisterHotKey` を使用するため、Windows 以外では動作しません)

### ビルドと確認

```powershell
cargo build --release
cargo fmt
cargo clippy --all-targets
cargo test
```

ビルドした exe は `target\release\autoqv.exe` に出力されます。開発中は `cargo run -- preview "Hello" --glyph-file glyphs.json` で直接実行することもできます。

### デバッグ方法

**経路をマウスを動かさずに確認する**

`preview` は入力を送らないため、レイアウトや経路計画の確認に使えます。折り返し・禁則・感度を変えたときの値の変化を、次のように比較できます。

```powershell
cargo run -- preview "Hello, World" --glyph-file glyphs.json --counts-per-em 300
cargo run -- preview "Hello, World" --glyph-file glyphs.json --line-width-em 5 --no-kinsoku
```

データに無い文字は「未収録」として行・列つきで表示されるので、データ不足の確認にも使えます。ストロークデータの自動取得を試したくないときは、`--offline` と `--glyph-file` を組み合わせると、ネットワークに接続せずに確認できます。

`write --dry-run` は `preview` と同じサマリーを表示しますが、未収録文字をログファイルに記録する点が異なります。ログ出力の確認に使えます。

**実機に入力を送らずに `write` の流れを確認する**

`write` はホットキーの待機状態に入った時点では入力を送りません。VRChat などに切り替えずに、待機中に `Alt+C` を押すと何も送らず終了するので、ホットキーの登録や待機の動作だけを確認できます。ホットキーが他のアプリと衝突する場合は `--start-hotkey` / `--abort-hotkey` で変更してください。

**設定ファイルの確認**

`--config` で指定した設定ファイルの内容は、`preview` の出力(推定時間・移動距離)に反映されます。エラーメッセージにはファイルのパスとキー名が含まれます。

**ストロークデータのキャッシュを確認・やり直す**

キャッシュ先は `%APPDATA%\Harukoto Project\AutoQV` です。

```
manifest.json          取得元のコミット・変換バージョン・上流に無かった文字の一覧
LICENSES.txt           取得したデータの謝辞
hershey/rowmans.json   英数字・記号
kanjivg/<コードポイント>.json   ひらがな・カタカナ・漢字(1 文字 1 ファイル。例: あ = 03042.json)
```

- 特定の文字だけ取得し直したいときは、`kanjivg` 内のその文字のファイルを削除します(次回の実行で取得します)
- 「上流に無かった文字」として記録された漢字を試し直したいときは、`manifest.json` の `kanjivg.not_found` から該当のコードポイント(10 進数)を削除します
- すべてやり直したいときは、フォルダごと削除します
- 取得状況は、標準エラー出力に進捗として表示されます。リダイレクトした場合は 1 行ずつのログになります

**テストの実行**

```powershell
cargo test
cargo test executor
cargo test -- --nocapture
```

- モジュール名・テスト名の一部を指定すると、その範囲だけ実行できます(例: `layout` `planner` `hotkey` `executor`)
- `--nocapture` を付けると、テスト中の標準出力を表示します

**パニック時のバックトレース**

```powershell
$env:RUST_BACKTRACE = "1"
cargo test
```

**テストしやすい構造**

- `glyph` / `layout` / `planner` / `runner::timing` / `input::hotkey` は純粋なロジックで、入力デバイスなしでテストできます
- `runner::executor::execute` は `PenDriver` trait を受け取るため、実機の代わりにテスト用のドライバ(`executor.rs` のテスト内の `FakeDriver`)で、分割・中断・ボタン解放の動作を確認できます
- 入力を送らず集計だけする `DryRunDriver`(`input/dry_run.rs`)は `preview` で使っています

**マウスボタンが押されたままになった場合**

実機での動作確認中にプロセスを強制終了すると、ペンのボタンが押されたままになることがあります。マウスを 1 回クリックすると解除できます。通常の終了・中断・panic・Ctrl+C では自動的に解放されます(コンソールウィンドウを閉じた場合を除く)。

**ホットキーが登録できない場合**

`failed to register hotkey ... it may be in use by another application` と表示されたときは、他のアプリが同じキーの組み合わせを使っています。`--start-hotkey` / `--abort-hotkey` か設定ファイルの `[safety]` で、別のキーの組み合わせに変更してください。

### ディレクトリ構成

```
src/
├─ cli/         コマンドライン引数とサブコマンド
├─ config/      設定ファイルの読み込みと検証
├─ dataset/     ストロークデータの取得・変換・キャッシュ
├─ glyph/       ストロークデータのモデルと読み込み
├─ layout/      テキスト → 配置済みストローク(折り返し・禁則)
├─ missing_log/ 未収録文字のログ出力
├─ planner/     配置済みストローク → 操作列(PenDown / PenUp / Move)
├─ input/       入力デバイス(SendInput・ホットキー・dry-run)
└─ runner/      操作列の実行(ステップ分割・待機・中断)
```

## ライセンスとデータの出典

ストロークデータは本リポジトリにも exe にも含まれません。次のデータを実行時に取得して利用します(変換後のデータはキャッシュ先に保存され、謝辞は同じ場所の `LICENSES.txt` に書き出されます)。

- [Hershey Fonts](https://github.com/kamalmostafa/hershey-fonts)(Roman Simplex): 英数字・記号。A. V. Hershey 博士と James Hurt 氏による
- [KanjiVG](https://github.com/KanjiVG/kanjivg): ひらがな・カタカナ・漢字。Ulrich Apel 氏による。CC BY-SA 3.0。変換後のデータも同じライセンスです
